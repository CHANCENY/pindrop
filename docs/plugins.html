Plugins

Plugins are the core building blocks of Pindrop CMS. Every feature in the system is delivered as a plugin.

Key Concept:
Each plugin is stored as a separate branch in the official repository.

📦 Plugin Repository

All plugins are available in the official repository:

https://github.com/CHANCENY/pindrop-features

Each branch represents a standalone plugin.

🌿 Branch = Plugin

The repository follows a strict convention:

  • Each branch contains one plugin
  • The branch name is the plugin name
admin → Admin plugin
payments → Payments plugin
analytics → Analytics plugin

⬇️ Downloading a Plugin

To download a plugin, clone its branch: 

git clone -b <plugin-name> --single-branch https://github.com/CHANCENY/pindrop-features.git

Example:

git clone -b admin --single-branch https://github.com/CHANCENY/pindrop-features.git
This will download only the selected plugin.

📁 Installing a Plugin

After downloading, move the plugin into your project’s modules directory: 

your-project/
  modules/
    admin/

The folder name must match the branch name.

⚙️ Enabling & Disabling Plugins

Plugins are managed via configuration:

config/sync/core.plugin.yml

Example:

admin: 1
payments: 0
  • 1 → Installed and enabled
  • 0 → Installed but disabled

The key must match the plugin name (branch name and folder name).

📏 Naming Rules

  • Use lowercase names
  • No spaces (use - or _ if needed)
  • Branch name = Folder name = Config key

🚀 Best Practices

  • Keep plugins independent
  • Do not modify core system files
  • Use clear and consistent naming
  • Version plugins through Git branches
Plugins should be self-contained and not depend on internal core changes.

🧠 Summary

  • Plugins live in Git branches
  • Clone the branch to download
  • Place in modules/
  • Enable via configuration
