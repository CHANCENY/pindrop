Authentication

Pindrop CMS authentication is provided by the admin plugin. It handles login, logout, registration, email verification, and password reset. All auth routes are public by default and use a session-based mechanism backed by the database.

Requirement: The admin plugin must be installed and enabled for authentication to work. Auth routes are registered in modules/admin/routing.yml.
---

Auth Routes at a Glance

Route name URL Methods Access
user.login /user/login GET, POST Public (anonymous only)
user.logout /user/logout GET, POST Any authenticated role
user.register /user/register GET, POST Public
user.forgot_password /user/forgot-password GET, POST Public
user.reset_password /user/reset-password/[token] GET, POST Public (token-gated)
user.verify_email /user/verify-email/[token] GET Public (token-gated)
---

Login

Login is handled by AdminController::login(). The user submits their email and password. The controller looks up the user by email, verifies the password using PHP's password_verify(), and then creates a session record in the database.

What happens step by step

  1. User visits /user/login and submits the form with email and password.
  2. The controller loads the user by email: User::loadByEmail($email, $db).
  3. Password is verified. Banned and suspended accounts are rejected with a clear message.
  4. A CurrentUser session record is created with: user ID, PHP session ID, IP address, user agent, and a 24-hour expiry.
  5. The response sets a session_id cookie (HTTP-only, secure) and redirects to the user's profile page.
After login, the session is stored in the database and the browser receives a session_id cookie. Every subsequent request, the AuthMiddleware reads this cookie, looks up the session, and resolves the current user.

Login form fields

POST /user/login

email    = user@example.com
password = secret
---

Logout

Logout is handled by AdminController::logout(). It reads the active PHP session ID, finds the matching CurrentUser database record, deletes it, clears the session_id cookie, and redirects to /user/login. 

GET /user/logout
Logout is a full server-side invalidation. The session record is deleted from the database, not just the cookie. Visiting protected pages after logout will redirect back to /user/login.
---

Registration

New users register at /user/register. The form requires a username, email, password, and password confirmation. On success the user is created with status pending and role user. An email verification token is generated. The account becomes fully active after the email is verified.

Registration form fields

POST /user/register

username         = johndoe
email            = john@example.com
password         = secret
password_confirm = secret
---

Password Reset

The forgot-password flow creates a time-limited token via UserVerification::createPasswordResetToken(). The reset link is /user/reset-password/{token}. After a successful reset all other active sessions for that user are revoked automatically.

---

AuthMiddleware

The admin plugin registers AuthMiddleware globally in middleware.yml. It runs on every request and enforces the _permission requirement declared on each route.

How permissions work:
A route with _permission: ['admin', 'super_admin'] will only pass if the current user's role matches one of the listed values. Routes with an empty requirements: {} block are public. Authenticated users trying to access a public-only route (like /user/login) are redirected to / automatically. 
# routing.yml example — protected route
admin.dashboard:
  path: '/admin'
  methods: ['GET']
  defaults:
    _controller: '...'
  requirements:
    _permission: ['admin', 'super_admin']

# routing.yml example — public route
user.login:
  path: '/user/login'
  methods: ['GET', 'POST']
  defaults:
    _controller: '...'
  requirements: {}
---

Session Storage

Sessions are stored in the database using the CurrentUser entity, not PHP's default file-based sessions. Each session row holds the user ID, session token, IP address, user agent, creation time, and expiry time (default 24 hours).

The current_user service is available in the DI container and in controllers: 

$currentUser = getAppContainer()->get('current_user');
$user = $currentUser->getUser(); // returns a User object or null
