Getting Started

Welcome to Pindrop CMS

Pindrop is a modular, developer-first PHP CMS built around a plugin architecture. The core stays minimal — every feature from authentication to content management is delivered as a plugin you opt into.

🧩

Plugin-based

Every feature is a plugin. Enable what you need, ignore what you don't.

🔌

YAML-driven

Routes, services, menus, middleware — all declared in YAML, no code changes needed.

🎨

Twig templates

Auto-escaping Twig with theme and plugin namespaces. Override anything.

🗄️

PDO + PreparedSQL

All database access uses prepared statements through a lightweight PDO wrapper.

📡

Event system

Subscribe to entity, user, and auth lifecycle events from any plugin.

💻

CLI tools

Manage schemas, plugins, and site settings from the terminal via ./pindro.

Core Architecture

All HTTP requests enter through index.php, which bootstraps the application via bootstrap.inc. Bootstrap initialises the DI container, loads services, discovers plugins, registers routes, and hands off to the router.

Request → index.php → bootstrap.inc → ServiceProvider (DI)
       → PluginManager (discover plugins)
       → RouteManager (register routes + middleware)
       → AuthMiddleware (check permissions)
       → Controller::method()
       → Twig template → Response

Plugin Distribution

Plugins are distributed as Git branches in a central repository. Each branch is one plugin; the branch name is the plugin ID.

# Download any plugin
./pindro plugin:download <plugin-name>

# Or clone manually
git clone -b admin --single-branch https://github.com/CHANCENY/pindrop-features.git modules/admin

Mandatory Plugins

Required

Two plugins must always be installed: admin (provides authentication and the admin UI) and terminal_command (provides CLI commands including db:schema:create). The CMS will not function without them.
