Core

Database

Pindrop wraps PDO in a DatabaseService that provides prepared statements, transactions, schema helpers, and logging integration. All queries are parameterised — string interpolation into SQL is never needed.

Configuration

Set these values in your .env file:

DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=my_database
DB_USERNAME=my_user
DB_PASSWORD=secret
DB_CHARSET=utf8mb4

Accessing the Service

// In a controller or service
$db = getAppContainer()->get('database');

// Or inject via services.yml
my_plugin.service:
  class: Simp\Pindrop\Modules\my_plugin\src\Services\MyService
  arguments:
    - "@database"

Running Queries

// SELECT — returns PDOStatement
$stmt = $db->query('SELECT * FROM users WHERE role = ?', 'admin');
$users = $stmt->fetchAll(PDO::FETCH_ASSOC);

// Named params
$stmt = $db->query('SELECT * FROM users WHERE id = :id', 42);
$user = $stmt->fetch(PDO::FETCH_ASSOC);

// INSERT
$db->query(
    'INSERT INTO articles (title, content, author_id) VALUES (?, ?, ?)',
    'My Title', '<p>Hello</p>', 1
);
$newId = $db->getPdo()->lastInsertId();

// UPDATE
$db->query(
    'UPDATE articles SET title = ?, updated_at = NOW() WHERE id = ?',
    'New Title', 42
);

// DELETE
$db->query('DELETE FROM articles WHERE id = ?', 42);

Convenience Methods

MethodReturnsDescription
query(string $sql, ...$params)PDOStatement|boolExecute any SQL with positional params
fetchAll(string $sql, ...$params)arrayExecute and return all rows as associative arrays
fetchOne(string $sql, ...$params)array|falseExecute and return the first row
insert(string $table, array $data)intBuild and run an INSERT, return last insert ID
update(string $table, array $data, string $where, ...$params)intBuild and run an UPDATE, return affected rows
delete(string $table, string $where, ...$params)intBuild and run a DELETE, return affected rows
tableExists(string $table)boolCheck if a table exists in the database
getPdo()PDOGet raw PDO instance for advanced operations
isConnected()boolCheck if connection is alive

Transactions

$pdo = $db->getPdo();

$pdo->beginTransaction();
try {
    $db->query('UPDATE accounts SET balance = balance - ? WHERE id = ?', 100, 1);
    $db->query('UPDATE accounts SET balance = balance + ? WHERE id = ?', 100, 2);
    $pdo->commit();
} catch (\Exception $e) {
    $pdo->rollBack();
    throw $e;
}

Schema Files

Each plugin can ship SQL schema files for its tables. Place them in modules/my_plugin/mysql/ using the filename as the table name:

-- modules/my_plugin/mysql/content_articles.sql
CREATE TABLE IF NOT EXISTS `content_articles` (
    `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT PRIMARY KEY,
    `entity_id`  INT UNSIGNED NOT NULL,
    `field_data` JSON NULL,
    `created_at` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    INDEX `idx_entity_id` (`entity_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Create all registered schemas:

./pindro db:schema:create
# Choose ALL, or select individual tables from the list
Never interpolate user input

Always use ? positional parameters or named :param placeholders. Never concatenate user-supplied values directly into SQL strings — even if they look safe.

Checking Connection

./pindro db:test
# Outputs: Connection: 1 (true) on success

Content entity tables

Each entity type registered in entity.repository.yml needs its own custom table (e.g. content_articles). These are created by providing SQL schema files in your plugin and running ./pindro db:schema:create.
