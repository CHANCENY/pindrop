Theming

Pindrop uses Twig 3 for all HTML rendering. Templates can live in the global themes/ directory or inside individual plugins. Both locations are registered as Twig namespaces and are available everywhere.

Auto-escaping is on. Twig is configured with autoescape: html by default. All variables are HTML-escaped unless you explicitly mark them safe with |raw.

Plugin templates

A plugin can ship its own templates in a templates/ directory inside the plugin folder: 

modules/
└── my_plugin/
    └── templates/
        ├── content/
        │   └── article.twig
        └── error/
            └── 404.html.twig

Twig Namespaces

Each theme registered in the themes/ directory gets its own Twig namespace matching its folder name. Each plugin's templates/ directory is also registered under the plugin's name. This lets you reference templates from anywhere without path ambiguity. 

{# From a global theme #}
{% extends '@admin/base.twig' %}

{# From a plugin template #}
{{ include('@my_plugin/content/article.twig') }}

{# Cross-referencing another plugin's template #}
{% include '@admin/auth/base.twig' %}
---

Rendering Templates from a Controller

All controllers extending ControllerBase have a renderTwig() helper that renders a template and returns a Symfony Response: 

<?php

use Simp\Pindrop\Controller\ControllerBase;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;

class MyController extends ControllerBase
{
    public function index(Request $request, string $route_name, array $options): Response
    {
        return $this->renderTwig('my_plugin/content/article.twig', [
            'page_title' => 'Hello World',
            'items'      => [1, 2, 3],
        ]);
    }
}

The first argument is the template path relative to any registered namespace. You can also pass a namespaced path: '@admin/dashboard.twig'.

---

Rendering Templates from Entity::getView()

Content entities render themselves via getView(). Use the Twig service directly: 

public function getView(): string
{
    return getAppContainer()->get('twig')
        ->render('@my_plugin/content/article.twig', ['entity' => $this]);
}

Template Variables

Variables you pass to renderTwig() are directly available in the template. The admin theme also injects global variables automatically (current user, menu items, flash messages).

Common variables in admin templates

VariableTypeDescription
page_titlestringPage <title> and heading
userarrayCurrent user data array
errorstring|nullForm or page error message
entityStorageEntityContent entity object (content templates)

Base Template Inheritance

The admin theme uses a base layout that child templates extend: 

{# themes/admin/templates/base.twig #}
<!DOCTYPE html>
<html>
<head>
    <title>{{ page_title }} — Pindrop</title>
</head>
<body>
    {% block sidebar %}...{% endblock %}
    {% block content %}{% endblock %}
</body>
</html>
{# Your plugin template #}
{% extends '@admin/base.twig' %}

{% block content %}
    <h1>{{ page_title }}</h1>
    <p>My content here</p>
{% endblock %}

Assets

Static assets (CSS, JS, images) for themes live in the theme's assets/ directory. The admin theme bundles Tagify (tag input), DataTables, and Font Awesome. Reference assets using their web-accessible path from the document root. 

<link rel="stylesheet" href="/themes/admin/assets/style.css">
<script src="/themes/admin/assets/tagify-4.36.0/dist/tagify.min.js"></script>
---

Plugin-Supplied Templates Override

If a plugin registers a template with the same namespace path as an existing template, the last registered plugin wins. To intentionally override an admin theme template from a plugin, mirror the same path in your plugin's templates/ directory: 

modules/
└── my_plugin/
    └── templates/
        └── admin/
            └── dashboard.twig   ← overrides themes/admin/templates/dashboard.twig
Override order depends on plugin load order. Use overrides carefully — they apply globally to all requests once the plugin is enabled.
---

Outputting Raw HTML

Because auto-escaping is enabled, HTML stored in fields (like the body of an article) must be marked safe when outputting: 

{# Safe — auto-escaped (shows raw HTML tags) #}
{{ entity.getContent() }}

{# Raw — renders HTML as markup #}
{{ entity.getContent()|raw }}
Only use |raw on content you control or have sanitised. Never apply it to unfiltered user input.
