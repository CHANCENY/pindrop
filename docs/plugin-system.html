Plugin System

Every feature in Pindrop is a plugin. Plugins live in the modules/ directory and are self-describing via YAML configuration files. The core framework stays minimal — plugins add routes, services, entities, middleware, menus, and CLI commands.

---

Plugin Structure

modules/
└── my_plugin/
    ├── info.yml                 ← required: plugin identity
    ├── routing.yml              ← HTTP routes
    ├── services.yml             ← DI container services
    ├── middleware.yml           ← request middleware
    ├── menu.yml                 ← admin sidebar links
    ├── entity.repository.yml   ← content entity registrations
    ├── autocomplete.yml         ← autocomplete handler registrations
    ├── settings.config.yml      ← settings panel handlers
    ├── pindro.commands.yml      ← CLI command scripts
    └── src/
        ├── Controller/
        ├── Entity/
        ├── Form/
        ├── Middleware/
        └── Services/

Creating a Plugin

Option A — CLI (recommended)

./pindro plugin:create

The CLI will ask for name, description, version, author, website, and license. It creates the plugin directory and scaffolds all YAML files automatically.

Option B — Manually

Create a folder in modules/ with your plugin's machine name (lowercase, underscores only). Add at least an info.yml file.

---

Installing & Enabling a Plugin

Via CLI

# Install (registers in config)
./pindro plugin:install my_plugin

# Enable
./pindro plugin:enable my_plugin

# Disable
./pindro plugin:disable my_plugin

# Uninstall
./pindro plugin:uninstall my_plugin

# Download from the official repo (git must be installed)
./pindro plugin:download admin

Via Admin UI

Navigate to /admin/plugins (requires admin or super_admin role). From there you can install, enable, disable, configure, and upload plugin ZIPs.

Via config file (manual)

# config/sync/core.plugin.yml
admin: 1              # installed and enabled
terminal_command: 1   # installed and enabled
my_plugin: 0          # installed but disabled
Values: 1 = installed + enabled  |  0 = installed but disabled. Remove the key entirely to unregister the plugin.

YAML File Reference

info.yml

Required in every plugin. Declares plugin identity and metadata.

name: "My Plugin"
description: "Does something useful"
version: 1.0.0
author: "Your Name"
website: "https://example.com"
license: "MIT"
---

routing.yml

Registers HTTP routes. Each route has a machine name (key), a path pattern, allowed HTTP methods, a controller reference, and access permissions. 

my_plugin.home:
  path: '/my-page'
  methods: ['GET']
  defaults:
    _controller: 'Simp\Pindrop\Modules\my_plugin\src\Controller\MyController::index'
  requirements:
    _permission: ['user', 'admin', 'super_admin']

my_plugin.public:
  path: '/public-page'
  methods: ['GET', 'POST']
  defaults:
    _controller: 'Simp\Pindrop\Modules\my_plugin\src\Controller\MyController::publicPage'
  requirements: {}    # empty = anonymous access only

Path parameters:

my_plugin.view:
  path: '/items/[id:int]'       # integer segment → $id
  # also: [slug:string], [token:string]

Available permission values: guest, user, moderator, admin, super_admin

---

services.yml

Registers services into the DI container. Arguments prefixed with @ reference other container services by name. 

my_plugin.service:
  class: Simp\Pindrop\Modules\my_plugin\src\Services\MyService
  arguments:
    - "@database"
    - "@logger"
  tags:
    - "my_plugin"

Core services available for injection:

Service nameWhat it is
@databaseDatabaseService — PDO wrapper
@loggerLoggerInterface — file or DB logger
@plugin.managerPluginManager
@filesystemFileSystem — stream wrapper file ops
@twigTwigEngine
@current_userCurrentUser — logged-in session
@content.factoryContent factory for entity instances
@content.repositoryContent repository for queries
@site.settingsSettings service
---

middleware.yml

Registers middleware classes that run on every request. Your class must implement the Middleware interface from simp/router. 

my_plugin.auth.middleware:
  class: Simp\Pindrop\Modules\my_plugin\src\Middleware\MyMiddleware
<?php

namespace Simp\Pindrop\Modules\my_plugin\src\Middleware;

use Simp\Router\middleware\access\Access;
use Simp\Router\middleware\interface\Middleware;
use Symfony\Component\HttpFoundation\Request;

class MyMiddleware implements Middleware
{
    public function __invoke(Request $request, Access $access, $next)
    {
        // Inspect $access->options for route requirements
        // Set $access->access_granted = true/false
        // Optionally set $access->redirect = new RedirectResponse('/somewhere')
        return $next($request, $access);
    }
}
---

menu.yml

Adds links to the admin sidebar. Links are grouped under a named group key and assigned a weight (lower = higher in the menu) and a role restriction. 

groups:
  admin:
    my_section:
      title: My Section
      route: my_plugin.home
      icon: fa fa-star
      weight: 10
      roles: [admin, super_admin]
---

entity.repository.yml

Registers content entity classes with the content repository so they appear in the admin content UI and are accessible via content.factory. 

article:
  class: Simp\Pindrop\Modules\my_plugin\src\Entity\Article
  description: "Article content type"
  category: "content"
  version: "1.0"

The key (article) is the entity machine name. See the Entities guide for the full entity class API.

---

autocomplete.yml

Registers autocomplete handlers that serve results to the /internal/autocomplete?source=... endpoint. The handler is a static method reference. 

autocomplete.my_source:
  handler: Simp\Pindrop\Modules\my_plugin\src\Plugin\MyAutocomplete::matchItems
<?php

class MyAutocomplete
{
    public static function matchItems(string $query, array $config): array
    {
        // Return array of ['value' => ..., 'label' => ...] matches
        return [];
    }
}
---

settings.config.yml

Registers a settings handler that adds a section to the /admin/settings page. Your class must implement SettingsInterface. 

settings:
  name: My Plugin Settings
  class: Simp\Pindrop\Modules\my_plugin\src\Plugin\MySettings
<?php

use Simp\Pindrop\Settings\SettingsInterface;
use Symfony\Component\HttpFoundation\Request;

class MySettings implements SettingsInterface
{
    public function settingKey(): string
    {
        return 'my_plugin.settings';
    }

    public function savableValues(Request $request): array
    {
        return ['some_key' => $request->request->get('some_key')];
    }
}
---

pindro.commands.yml

Registers CLI command scripts for use with the ./pindro CLI tool. Each entry points to a PHP file that returns an associative array of command names to function names. 

my_plugin.commands:
  name: "My Plugin Commands"
  script: "modules/my_plugin/cli/commands.php"
  status: true
<?php
// modules/my_plugin/cli/commands.php

return [
    'my_plugin:hello' => 'helloCommand',
    'my_plugin:sync'  => 'syncCommand',
];

function helloCommand(CLIPrinter $printer, ...$values): void
{
    $printer->printLine("Hello from my plugin!", GREEN);
}

function syncCommand(CLIPrinter $printer, ...$values): void
{
    // $values[1] contains $argv
    $printer->printLine("Syncing...", YELLOW);
}

Mandatory Plugins

Two plugins must always be installed and enabled. Without them the CMS will not function:
admin Provides authentication, admin UI, user management, content management, plugin management UI, and the AuthMiddleware. Without it there is no login page and no admin interface.
terminal_command Provides CLI commands including db:schema:create, which is required during installation to create all database tables.

Installing both via CLI

./pindro plugin:install admin
./pindro plugin:enable admin

./pindro plugin:install terminal_command
./pindro plugin:enable terminal_command

./pindro db:schema:create   # then select ALL

Or download them directly from the official plugin repository:

./pindro plugin:download admin
./pindro plugin:download terminal_command
